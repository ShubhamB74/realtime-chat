# Deployment

Status: Phase 1 (local development). Kubernetes arrives in Phase 8.

## Prerequisites
Docker with Compose v2, Go (see ADR-002 for the verified line), Node 22, Python 3.12, `make`, `curl`. `golangci-lint` is needed only for `make lint` locally; CI runs it via an action.

## First-time setup
```
make bootstrap      # creates .env, resolves Go/npm/pip dependencies and writes lock files
make up             # postgres, redis, objectstore (waits until healthy)
make migrate-up     # applies migrations (goose)
make test           # unit tests
make test-integration   # needs `make up` + `make migrate-up`; covers Postgres, Redis and the end-to-end API
make run            # backend on the host, then: make check-health
```
After `make bootstrap`, commit `backend/go.mod`, `backend/go.sum`, `frontend/package-lock.json`, `ai-service/requirements.lock` and `requirements-dev.lock`. CI and the Docker builds require them.

Other stacks: `make up-streaming` (adds Kafka and Kafka UI at http://127.0.0.1:8081), `make up-apps` (backend, frontend at :5173, ai-service at :8000, all in containers). `make down` keeps data; `make down-volumes` deletes it.

## Compose profiles
| Profile | Services | Needed from |
|---|---|---|
| `core` | postgres, redis, objectstore | Phase 1 |
| `streaming` | kafka (KRaft), kafka-ui | Phase 4B |
| `apps` | backend, frontend, ai-service | Phase 1 |

All published ports bind to 127.0.0.1. Data lives in named volumes.

## Health endpoints
- `GET /healthz`: liveness, never checks dependencies.
- `GET /readyz`: 200 only if PostgreSQL and Redis are up. Kafka and the object store are reported as optional. Returns 503 with `draining` during shutdown.

## Production template
`infrastructure/docker/docker-compose.prod.example.yml` shows hardened settings (read-only filesystem, dropped capabilities, resource limits, digest-pinned images, secrets from outside the repo). It is a template, not a deployable stack. Production data stores and orchestration are decided in Phase 8.

## Image pinning
Compose uses version lines for convenience. Before any shared or production use, pin every image by digest. Two images are currently unpinned (`objectstore`, `kafka-ui`) and are marked TODO.

## WebSocket gateway notes (Phase 3)
- **Run exactly one backend replica for now.** Live push is in-process; with two replicas, messages pushed from one are not delivered live on the other (clients would only see them after sync). Cross-replica routing arrives in Phase 4A (ADR-006).
- **Reverse proxies** must pass WebSocket upgrades and keep idle connections open longer than the 25 s ping interval. Behind TLS terminate with `wss://`.
- **Rolling restarts:** the server sends close code 1001 to every client and waits for them (up to `SHUTDOWN_TIMEOUT`). Clients reconnect with exponential backoff and jitter, then sync. A large simultaneous reconnect is not yet load-tested.
- The Vite dev proxy forwards `/api/v1/ws` (`ws: true`). Open `http://localhost:5173/ws-debug.html` for a manual test page.
- File descriptor limits: each connection uses one descriptor; raise `ulimit -n` for load tests above a few thousand connections.
